실제 팀 성적으로 검증해 공개하는 개인 프로젝트입니다.

## 1. 문제 정의

농구 기록을 볼 때마다 "그래서 이 선수가 얼마나 좋은 선수인가"를 한 숫자로 보고 싶었는데,
기존 공인 지표(PER, WS, BPM)는 계산식이 블랙박스에 가까워서 **점수가 왜 그렇게 나왔는지
분해해서 볼 수가 없었습니다.**

그래서 득점·효율·플레이메이킹·수비·승리기여 5개 축으로 **분해해서 볼 수 있는** 평가 지표를
직접 만들기로 했습니다. 다만 지표를 만드는 것보다 더 중요한 문제가 있었습니다 —
**내가 정한 가중치가 과연 의미 있는 값인지 어떻게 증명할 것인가.** 이 프로젝트의 실제 주제는
지표 설계가 아니라 그 검증입니다.

## 2. 접근

### 데이터 파이프라인
- basketball-reference.com에서 시즌별 3개 테이블(기본/고급/슛구역)을 수집
- 시즌마다 개별 JSON으로 저장하고 이미 받은 시즌은 건너뛰어 **중단 후 재개 가능**하게 구성
- 원본 HTML을 로컬 캐시에 보관해, 지표 공식을 바꿔도 네트워크 재접속 없이 전체 재계산

### 시대별 결측 처리
스탯 항목이 시대마다 다르다는 게 가장 큰 기술적 난점이었습니다.

| 항목 | 집계 시작 |
|---|---|
| 스틸·블록 | 1973-74 |
| 턴오버 | 1977-78 |
| 3점슛 | 1979-80 |
| 슛 구역별 데이터 | 1996-97 |

컬럼 자체가 없는 시즌은 중립값으로 채우고, **특정 선수만 기록이 빠진 경우엔 그 항목만
중립 처리하고 나머지 항목으로 점수를 계산**하도록 했습니다. 이 구분을 하지 않으면 결측값이
합계 전체로 전파되어 점수가 통째로 사라집니다(실제로 발생했던 버그 — 아래 참조).

### NDL Score 설계
5개 축을 z-score로 표준화해 가중합합니다. 효율성·플레이메이킹·수비기여는 빅맨과 가드의
구조적 유불리를 없애기 위해 **같은 포지션군 안에서만 상대평가**합니다.
출전시간이 적은 선수는 하드 컷오프로 제외하는 대신 점수를 평균 쪽으로 수축시킵니다.

### 가중치 학습 및 검증
초기 가중치(25/20/15/20/20)는 근거 없이 정한 값이었습니다. 이를 검증 가능한 값으로 바꾸기 위해:

1. **정답값 확보** — 팀별 실제 경기당 득실 마진을 외부 기준으로 삼음
2. **학습** — 팀 소속 선수들의 구성요소 평균이 그 팀의 마진을 얼마나 설명하는지로 가중치 학습
3. **정보 누수 차단** — 1952~2015년의 **홀수 연도 시즌으로만** 학습, 짝수 연도로 검증
4. **과적합 검증** — 학습에 전혀 쓰이지 않은 **2016~2024 구간을 별도 홀드아웃**으로 확보

### AI 활용 범위와 직접 판단한 부분
개발 도구로 Claude Code를 사용했습니다. **코드 작성(스크래핑, 페이지 구현)은 AI가,
문제 정의와 설계 판단은 제가** 했습니다. 구체적으로 제가 판단한 지점들:

- **순환논리 차단** — 제약 없이 가중치를 최적화하니 승리기여(WS·VORP 기반)가 83%를 가져갔습니다.
  두 지표 자체가 팀 성적에서 역산되는 값이라 당연한 결과였고, 그대로 두면 NDL Score는
  WS의 복잡한 재포장이 됩니다. 각 요소를 5~40%로 제한해 5개 축이 모두 살아있도록 했습니다.
- **검증 설계** — 같은 시즌 안에서 학습/검증을 나누면 정보가 새기 때문에 시즌 단위로 분리했고,
  현대 농구에서도 유효한지 보려고 홀드아웃 구간을 따로 뒀습니다.
- **데이터 품질 교차검증** — 검증용 팀 마진을 독립된 두 출처에서 각각 계산해 대조했습니다.
- **기능을 넣지 않기로 한 판단** — 아래 '시도했다 접은 것' 참조.

## 3. 결과

### 가중치 학습 전후 (팀 득실 마진과의 상관계수)

| 구간 | 시즌 수 | 기존 가중치 | 학습 가중치 | 개선 |
|---|---|---|---|---|
| 학습 (1952~2015 홀수) | 32 | 0.853 | 0.900 | +0.047 (29/32 시즌) |
| 검증 (1952~2015 짝수) | 32 | 0.864 | 0.910 | +0.046 (31/32 시즌) |
| **현대 홀드아웃 (2016~2024)** | 9 | 0.895 | **0.939** | **+0.044 (9/9 시즌)** |

세 구간의 개선폭이 +0.044~+0.047로 거의 같습니다. 과거 데이터에만 맞춘 것이라면
3점 혁명 이후 시즌에서 개선폭이 줄어야 하는데 그렇지 않았습니다.

### 학습된 가중치

| 구성요소 | 기존 | 학습 후 |
|---|---|---|
| 생산성 | 25.0% | 9.0% |
| 효율성 | 20.0% | 29.7% |
| 플레이메이킹 | 15.0% | 9.3% |
| 수비기여 | 20.0% | 12.0% |
| 승리기여 | 20.0% | 40.0% |

**볼륨 스탯(생산성)보다 효율이 팀 성적에 훨씬 중요하다**는 결과가 데이터로 나왔습니다.

### 데이터 품질 검증
검증용 팀 마진을 538 ELO 게임 로그와 NBA 팀 박스스코어에서 독립적으로 계산해 대조한 결과,
겹치는 **146개 팀-시즌에서 마진이 소수점 이하까지 완전히 일치**(최대 차이 0.0000)했습니다.

### 발견하고 수정한 버그
- **결측값 전파** — 1970-71 ~ 1974-75 시즌 선수의 90% 이상(총 1,409명)이 NDL Score가 비어 있었습니다.
  일부 선수만 기록이 없는 항목에서 결측값이 합계로 전파된 것이 원인이었고, 항목별 중립 처리로 해결했습니다.
- **시즌 선택 시 화면 공백** — 위 결측값 때문에 특정 시즌을 고르면 표가 통째로 비었습니다.
  값이 없는 선수를 렌더링 단계에서 걸러내도록 수정했습니다.
- **형변환 오류** — 초기 두 시즌에서 출전시간 결측이 정수 변환 단계까지 전파되어 수집이 실패했습니다.

## 4. 한계와 개선점

### 알고 있는 한계
- **공인 지표보다 설명력이 낮습니다.** 73개 시즌 평균 상관계수 기준 NDL Score 0.890,
  WS 0.941, BPM 0.987입니다. 다만 WS·BPM은 애초에 팀 성적에 맞춰 설계된 지표라 이 검증에서
  구조적으로 유리하며, NDL Score의 목적은 최고 정확도가 아니라 **5개 축으로 분해해 볼 수 있는 것**입니다.
- **옛날 시즌은 평가 축이 부족합니다.** 1973-74 이전 시즌은 스틸·블록 기록 자체가 없어
  수비기여 축이 사실상 작동하지 않습니다.
- **시뮬레이션은 1996-97 이후만 지원합니다.** 엔진이 구역별 슛 선택으로 포제션을 계산하는데,
  슛 구역 데이터가 그 이전에는 집계되지 않아 구역 분포가 균등값으로 채워집니다. 그 상태로
  시뮬레이션하면 결과가 의미를 갖지 못해 의도적으로 제외했습니다.
- **검증 구간이 2024년까지입니다.** 사용한 공개 데이터셋이 그 이후를 커버하지 않습니다.
- **선수 얼굴 이미지는 최근 시즌 위주입니다.** 옛날 시즌 선수는 이미지 없이 기록만 표시됩니다.

### 시도했다 접은 것
선수의 수비 스탯에서 "팀 환경 덕분에 얻은 몫"을 분리하려고, 동료들의 수비 지표를 출전시간
가중 평균한 값(본인 제외)에 대해 Ridge 회귀를 돌려 잔차를 개인 기여분으로 쓰는 방식을 만들었습니다.
**검증해보니 개선폭이 +0.002 수준이라 도입하지 않았습니다.** 대신 같은 회귀 아이디어를
가중치 학습에 적용한 것이 훨씬 효과적이었습니다(+0.044).

부수적으로, 회귀계수가 음수로 나온 것은 의미가 있었습니다 — 동료가 수비를 잘할수록
개인의 리바운드·스틸 점유율이 깎이는 **제로섬 경쟁 효과**가 데이터에 잡혔습니다.

### 재현성 제약
프로젝트 진행 중 basketball-reference가 Cloudflare JS 챌린지(`cf-mitigated: challenge`)를 적용해
비브라우저 클라이언트의 접근을 차단했습니다. robots.txt조차 403이고 모회사 도메인도 동일한 것으로 보아
특정 IP 차단이 아니라 사이트 정책 변경으로 판단됩니다. 현재 원본 재수집은 불가능하며,
**로컬 캐시에 보관해둔 HTML로 전체 재계산은 가능**합니다. 검증용 팀 성적 데이터는
공개 데이터셋 두 종으로 대체했습니다.

### 다음에 할 것

## 실행 방법

```bash
pip install -r requirements.txt

python data/fetch_all_seasons.py          # 시즌별 수집 (캐시 있으면 재계산만)
python data/fetch_all_seasons.py --force  # 공식 변경 후 전체 재계산
python data/fetch_team_margins.py         # 검증용 팀 득실 마진 수집
python data/optimize_weights2.py          # 가중치 학습 (제약 조건 비교)
python data/holdout_modern.py             # 현대 홀드아웃 검증
python data/validate_ndl.py               # 전체 시즌 검증
python data/build_multiseason.py          # 웹 임베드용 데이터 생성 (5종)
python data/build_ndl_page.py             # 페이지 빌드 (stats/player/scatter/game 동일 패턴)
```

## 구조

```
data/
  fetch_all_seasons.py      시즌별 수집 + NDL Score 계산 (캐시 기반 재실행 지원)
  fetch_team_margins.py     검증용 팀 득실 마진 (538 ELO + NBA 팀 박스)
  optimize_weights.py       가중치 학습 (무제약)
  optimize_weights2.py      가중치 학습 (제약 조건 3종 비교) ← 채택안 산출
  holdout_modern.py         2016~2024 홀드아웃 검증
  validate_ndl.py           전체 시즌 검증 (WS·BPM과 비교)
  build_multiseason.py      웹 임베드용 압축 데이터 생성
  build_*_page.py           템플릿 + 데이터 → 발행용 HTML
  *_template.html           페이지 템플릿 (데이터 자리는 플레이스홀더)
pages/                      빌드 결과물
```

데이터 파일(`data/seasons/`, `data/.cache/`, 대용량 CSV·JSON)은 용량 문제로 저장소에서 제외했습니다.
`fetch_all_seasons.py`로 재생성할 수 있으나, 위 '재현성 제약' 항목을 참고하세요.
